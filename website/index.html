PAGE 002JOB CONTROL — EXECCONT'D FROM 001

Bring your logic to the data.

Stored procedures in WormDB are native Zig functions compiled into the server binary. Call them with one EXEC request over WormWire. Handlers can work with keys, publish events, and query vectors without a series of application-to-database round trips.

Built-in handlers cover counters, audit proofs, agent memory, coordination, and vector search. Extend the registry or register procedures from an external domain package when embedding the engine.

Locking and durability are explicit. Some helpers write only to memory until the next snapshot; durable helpers have different locking behavior. Choose the right contract for each handler. Read the procedure guide.

Build around an append-only audit history, an application event stream, or searchable agent memory. The same engine provides the storage and the operations around it.

0x02 · SET

Write-once records

Set a key with the WORM flag and normal SET and DEL commands reject changes to it. Use the append-log procedures for Merkle proofs, signed checkpoints, and witness receipts.

0x57 0x57 · HELLO

A compact binary protocol

WormWire uses a two-byte handshake, an opcode, and length-prefixed payloads. The Bun TCP client and browser WebSocket client handle framing for you; Redis and text clients are not compatible.

0x06 · SUB

Pub/sub that matches prefixes

Subscribe to a channel or prefix and receive matching EVENT frames on the same connection. Use it for application events or to follow vector insert notifications by namespace.

0x05 · CLUSTER

Peer discovery and replication

On Linux, MeshGuard provides peer discovery and failure detection. WormDB replicates committed writes and synchronizes joining peers. Configure trust and transport protection for your network.

0x0D · VINSERT

Vectors live with your data

Store embeddings as keys, then query a per-namespace HNSW index, a quantized prefilter, or exact search. Cosine, dot product, and L2 metrics use SIMD distance kernels.

0x09 · EXEC

Procedures compiled into the binary

Run native Zig handlers with access to the store, events, and cluster. Built-in memory and audit procedures give you a starting point; your handler chooses its locking and persistence behavior.

PAGE 004VECTOR SEARCHKEYS + CONTEXT

Your vectors belong with your records.

Embeddings are ordinary vec:<ns>:<id> keys backed by the write-ahead log. A derived index accelerates search within each namespace. Native vector inserts and the Bun vector wrapper default to WORM; mutable vectors are an explicit choice.

  1. HNSW graphTraverse a per-namespace graph and refine candidates with the selected metric.
  2. Quantized prefilterRank a smaller candidate set with binary hashes, then refine using the original vectors.
  3. Exact searchScan the vectors directly when requested or when no suitable index is available.

vsearch searches one node. vsearch_cluster is the separate fan-out procedure. Rebuild derived indexes with vreindex after raw ingestion or WAL recovery beyond the last snapshot.

PAGE 005REPLICATION TOPOLOGY0x05 · CLUSTER STATUS

Start local. Connect peers on Linux.

MeshGuard supplies SWIM gossip, node identity, and WireGuard integration. WormDB adds best-effort replication and full-state synchronization for joining peers.

  • Discovery — a new node joins through a seed and learns its peers.
  • Trust — configure org-trust grants and node certificates for replication authorization.
  • Transport — replication uses TCP; verify that the actual route is protected by a tunnel or another secure transport.
  • Write behavior — the local commit is authoritative. Replication failures are logged without failing the client write.

Replication does not provide quorum acknowledgements. Windows currently supports single-node operation.

FOLLOW A WRITE
Client → local node
